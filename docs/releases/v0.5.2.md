# Context Mole v0.5.2

Context Mole v0.5.2 fixes two causes of indexing getting stuck on "Waiting for CPU or memory" ([#1](https://github.com/JPCodeCraft/Context-Mole/issues/1)), fixes a database error that could appear after hours of indexing, and logs what indexing is waiting on when it waits for a long time.

There is no reindex and no database schema change, so you don't need to do anything after updating.

## Indexing no longer waits on the OCR model download

- A scanned PDF or an image used to keep its CPU slot while the OCR model was being downloaded. On a slow or stuck download, every other file waited behind it with "Waiting for CPU or memory". Files that need OCR now give their slot back while the model downloads, so other files keep indexing.
- A model download that stops receiving data now fails after 2 minutes instead of waiting for hours. The next attempt resumes from the bytes already received, and if the server refuses to resume, the download starts again from the beginning. This applies to the OCR models and the semantic search model.
- After an OCR model download fails, files that need OCR stop retrying it for 5 minutes, instead of each page of each file trying again in turn. **Settings → Document OCR** still retries right away.

## Database reads under load

Context Mole now uses Microsoft.Data.Sqlite 10.0.15. Version 10.0.11 had a race in its connection pool that could give the same database connection to two callers at once. When it happened, project refreshes failed repeatedly with SQLite error 4 ("not an error", "another row available" or "abort due to ROLLBACK"), and a file could fail to index with "Cannot access a disposed object".

## Logs for stuck indexing

When a file has waited more than 5 minutes for a CPU slot or source memory, the log (`%LOCALAPPDATA%\ContextMole\logs`) now gets a warning. It shows how many CPU slots are in use and whether OCR or semantic embedding has taken them, how many files are waiting, the source memory reserved, and which files are in progress and for how long. The warning repeats every 15 minutes while the wait lasts, at most one line a minute for all files together. If indexing gets stuck, this line shows what it is waiting for.

## Install and update

Download [JPCodeCraft.ContextMole-win-x64-Setup.exe](https://github.com/JPCodeCraft/Context-Mole/releases/download/v0.5.2/JPCodeCraft.ContextMole-win-x64-Setup.exe) for Windows 10+ x64. Existing installed Windows builds can obtain this release through their normal update check. Reload your AI clients' MCP connection after updating.

If updates fail and the log shows "An attempt was made to access a socket in a way forbidden by its access permissions", a firewall or security product is blocking Context Mole's internet access. Download the installer above instead, and allow Context Mole through the firewall so that it can download the OCR and semantic search models.

Windows releases remain unsigned, so SmartScreen may show an unrecognized-app warning. Native Linux and macOS packages are not included.
