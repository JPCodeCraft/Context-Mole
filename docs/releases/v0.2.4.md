# Context Mole v0.2.4

Context Mole v0.2.4 restores CPU-driven indexing parallelism, keeps native-memory cleanup without admission throttling, and fixes retry and development-build reliability.

## Indexing throughput and memory cleanup

- Document parallelism is derived from the selected CPU profile and the machine's logical CPU count, without a separate memory-admission limiter reducing work to one file.
- OCR remains serialized while temporarily receiving the full processor capacity allowed by the selected profile.
- Per-operation resources are disposed promptly, OCR and embedding sessions still unload after idle periods, and disposable vector caches are cleared under genuine system-memory pressure.
- Indexing activity now reports processor-capacity waits without misleading memory-admission or exclusive-file states.

## Failed-file retry

- Retry now distinguishes files newly queued from files that are already queued or processing, instead of reporting that no failed files needed retrying.
- Error cards remain until the queued retry succeeds, and the status message now explains that behavior.
- Errors for files removed from the project are cleared so they cannot leave a permanently ineffective Retry button.
- Transient embedding-refresh interruptions remain eligible for automatic recovery.

## Development and build reliability

- Development brokers run from immutable staged snapshots outside project build output, preventing the shared broker from locking assemblies during subsequent builds.
- Concurrent clients continue to share one broker process, while rebuilt development payloads receive a fresh staged deployment.
- The repository now pins the .NET 10.0.400 SDK used by local and release builds.
