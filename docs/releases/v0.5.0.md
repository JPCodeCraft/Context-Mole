# Context Mole v0.5.0

Context Mole v0.5.0 reads more of your Office and OpenDocument files, keeps PDF columns in reading order, labels spreadsheet values with the right column names, and ranks keyword matches by how close the query words are.

## One full reindex after updating

This release changes how documents are extracted and prepared for search (preparation `layout-v7/spans-v4/body-context-v6`). After the update, every document in every project is re-extracted once in the background, **including OCR of scanned pages and images**, the next time its folder is scanned. Large projects, and projects with many scans, can take as long as their first indexing did.

You don't need to do anything. Existing evidence stays searchable until each document's replacement is committed, paused projects wait for Resume, and source files are never changed. Keep the source folders available so the reindex can finish. There is no database schema change in this release.

## Office and OpenDocument files

- Text inside Word content controls (the boxes used by forms and templates) is now indexed. It was skipped before.
- PowerPoint slide titles become the heading for the slide's text, tables, speaker notes and comments.
- PowerPoint, ODT and ODP tables are indexed as tables, with one row per line. Meaning-based search sees each value with its column name, and table cells are no longer repeated as loose paragraphs.
- ODP slide names become headings. LibreOffice's default names ("page1", "page2") are ignored.
- Tables with merged cells carry a `table_spans` warning, because their column alignment is uncertain.

## Spreadsheets

- A title row above a table's header row is kept as the table's caption, and the values below are paired with the real header.
- A second table further down a sheet, after a blank row, gets its own column names when its header is followed by numbers or dates, or when it uses different columns. A text-only data row after a blank row is still treated as data.

## PDFs and OCR

- Multi-column pages keep each column in reading order across paragraph gaps, narrow column gutters and running headers or footers that sit close to the text.
- Scanned PDFs whose hidden text layer is garbled are detected, and the garbled regions are replaced by OCR text. Readable native text, including code and technical notation, is kept and does not trigger OCR.
- OCR keeps complete prose paragraphs apart while still joining short label and value pairs, such as on cards and forms.
- On pages with no Chinese or Japanese text, OCR no longer reads lone dashes as 一 or 二.

## Search

- Keyword ranking favors passages where the query words appear close together, and passages that match more of the optional words.
- Section searches favor sections where several passages match the meaning of the query.
- When a query contains codes or acronyms, such as part numbers, ticket IDs or "GDPR", meaning-based previews of long passages show the part of the passage that contains them.
- Previews prefer substantive passages over a bare heading, a sheet's header row or an email's header block, and two previews from the same section no longer show overlapping text.
- An email's header block (From, To, Subject) is now included in meaning-based search.

## Install and update

Download [JPCodeCraft.ContextMole-win-x64-Setup.exe](https://github.com/JPCodeCraft/Context-Mole/releases/download/v0.5.0/JPCodeCraft.ContextMole-win-x64-Setup.exe) for Windows 10+ x64. Existing installed Windows builds can obtain this release through their normal update check. Reload your AI clients' MCP connection after updating.

Windows releases remain unsigned, so SmartScreen may show an unrecognized-app warning. Native Linux and macOS packages are not included.
