# Context Mole v0.5.1

Context Mole v0.5.1 fixes how Outlook `.msg` emails are indexed and opened, and makes the error filter in `list_documents` find every file with errors.

## Only Outlook emails are re-extracted

This release keeps the v0.5.0 preparation (`layout-v7/spans-v4/body-context-v6`), so it does **not** start another full reindex. If the v0.5.0 reindex is still running, it simply continues.

At startup, Context Mole finds the documents whose Outlook email headers were indexed incorrectly and re-extracts only those, in the background. That covers standalone `.msg` files and `.msg` emails attached to other emails or stored in archives. Their existing evidence stays searchable until each replacement is committed. There is no database schema change, so you don't need to do anything.

## Outlook .msg emails

- Email headers now show the real sender and recipients, such as `From: Ana Souza <ana@example.com>`, with To and Cc on separate lines, and Bcc when the message records it. Before, they showed internal type names such as `MsgReader.Outlook.Storage+Sender`. Since v0.5.0 these headers are also part of meaning-based search, so this fixes those results too.
- Forwarded emails inside a `.msg` get the same headers, body and attachments as the outer email. Before, their headers had no recipients.
- `materialize_content` can open attachments inside `.msg` emails again. It used to fail with a "MsgReader.Rtf.Font" error, because the MCP server never set up the older text encodings that Outlook messages need.

## Document list

- `list_documents` with status `error` returns every document with recorded errors, including one that shows as `pending` because its retry or reindex is queued. During the v0.5.0 reindex it returned none.

## Install and update

Download [JPCodeCraft.ContextMole-win-x64-Setup.exe](https://github.com/JPCodeCraft/Context-Mole/releases/download/v0.5.1/JPCodeCraft.ContextMole-win-x64-Setup.exe) for Windows 10+ x64. Existing installed Windows builds can obtain this release through their normal update check. Reload your AI clients' MCP connection after updating.

Windows releases remain unsigned, so SmartScreen may show an unrecognized-app warning. Native Linux and macOS packages are not included.
