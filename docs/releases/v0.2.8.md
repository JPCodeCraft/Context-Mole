# Context Mole v0.2.8

Context Mole v0.2.8 improves database startup and diagnostics, and measures document processing time without queue waits.

## Database startup and MCP diagnostics

- The desktop app completes database migrations and interrupted-job recovery before opening its normal interface.
- Migration history is validated before changes begin. Each migration runs in its own transaction, and a failed migration can be retried on the next launch.
- Startup failures show a clear error with the database and log paths, preserving the existing index for diagnosis.
- Logs include application versions, resolved paths, current and expected schema versions, migration outcomes and durations, and database readiness.
- The MCP broker preserves the underlying database error. Missing indexes, incompatible schemas, and access, locking, or corruption failures are reported distinctly.

## Document processing time

- Queued documents and files waiting for processor capacity show no running timer.
- Processing time starts when processor capacity has been acquired and excludes availability checks and queue waits.
- The completed average uses successful attempts' processing time for the current session. Failed and canceled attempts are excluded.
- The same timing rules apply when embeddings are refreshed.

## Update and reconnect

This release includes updated desktop, MCP server, and broker binaries. After updating, open Context Mole to complete database startup, then reload your AI client's MCP connection so it launches the updated server.

Daily UI and broker logs are available in `%LOCALAPPDATA%\ContextMole\logs`, or in the `logs` folder of your custom data directory.
