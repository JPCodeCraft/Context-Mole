# Context Mole v0.2.0

Context Mole v0.2.0 gives AI agents direct control over how the local index is searched and adds a safe, explicit Windows uninstall flow.

## Agent-directed search

- `search_project` now uses a breaking, structured-only request: agents choose `keyword`, `semantic`, or `hybrid` retrieval and can combine `must`, `should`, and `must_not` clauses with term, phrase, and prefix matching.
- Lexical search now ranks body text and document metadata independently, including titles, headings, filenames, paths, attachment or archive-entry names, worksheet names, and email subjects. Agents can override every field weight and both hybrid branch weights.
- Semantic results favor recall: borderline matches remain visible with raw scores and `low_confidence` unless strict filtering is explicitly requested. Hybrid search reports when it falls back to keyword retrieval; semantic-only search reports when semantic retrieval is unavailable without changing modes silently.
- Results are grouped by stable content IDs for root files, attachments, and archive entries. Responses expose stable passage and document IDs, provenance, attachment chains, locations, per-branch signals, clause matches, collapsed counts, and suppressed-source summaries.
- Agents can focus a later search on returned content IDs, read neighboring indexed passages, or materialize one authorized content item for original-format inspection.
- Indexing now supplies labelled metadata to semantic retrieval and uses stronger structural boundaries around headings, pages, slides, worksheets, email sections, attachments, archives, and table headers while keeping displayed excerpts clean.

The MCP server advertises the new schema and usage guidance directly to connected agents. Existing callers that construct `search_project` arguments themselves must update to the new structured contract; the previous free-form search shape is not supported.

On first launch, v0.2 discards earlier derived passages, embeddings, and full-text rows and rebuilds retained projects from their source files. Project and folder configuration remains in place; search coverage can be temporarily incomplete until that one-time background reindex finishes.

## Safe Windows uninstall

- Installed, non-portable Windows builds now include **Uninstall Context Mole…** in Settings.
- **Keep data** is selected by default. An explicit destructive choice can instead remove indexes, downloaded models, settings, temporary materializations, and logs under `%LOCALAPPDATA%\ContextMole` after the application and MCP sidecars release them.
- Custom `CONTEXTMOLE_DATA_DIR` locations are never deleted automatically. Indexed source files and managed AI-client connection entries are never removed.
- Cleanup uses process leases, a shutdown marker, strict path and reparse-point validation, and bounded retry handling. If locked data remains, the application uninstall completes and Windows shows the exact path for manual removal.
- The ordinary Windows Installed apps and direct Velopack uninstall paths are unchanged and continue to keep local application data.

## Install

Download [JPCodeCraft.ContextMole-win-x64-Setup.exe](https://github.com/JPCodeCraft/Context-Mole/releases/download/v0.2.0/JPCodeCraft.ContextMole-win-x64-Setup.exe) for Windows 10+ x64. Releases are currently unsigned, so Windows SmartScreen may show an unrecognized-app warning.

For the complete search schema, examples, data behavior, and manual MCP setup, see the [README](https://github.com/JPCodeCraft/Context-Mole#agent-directed-search).
